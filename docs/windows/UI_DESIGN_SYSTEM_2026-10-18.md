# ChatAssistant Lite UI 设计系统（D-UI，2026-10-18）

## 方向：哑光纸 + 青瓷

这不是一个“通用 SaaS 仪表盘”。它是一张安静的单人工作台：用户一边看微信聊天，
一边等少量、可核对的回复建议。设计目标按优先级排序：

1. 先让用户看清“现在是哪个会话、用的哪个后端/模型、建议是否有效”；
2. 把注意力留给聊天画面与建议，不让装饰抢戏；
3. 所有危险动作（发送、切换会话、改动 Key）都要有清楚的状态与确认。

视觉语义因此选择“纸、墨、青瓷”：暖纸色背景降低整屏亮度，墨绿文字保证阅读，
单一青瓷色只用于主按钮、选中态与可交互提示。避免蓝紫渐变、玻璃拟态、卡片阴影墙
这些与产品个性无关的默认语言。

| `accent` | `#176B5B` | 主按钮、选中态、青瓷强调 |
| `accent-hover` | `#12574A` | 主按钮 hover |
| `accent-soft` | `#E7F1EC` | 选中行、提示底 |

| `warn` | `#96661F` | 授权/额度提示 |

| `preview` | `#F1EFE8` | 聊天画面占位/空状态底 |

- 字体：`Microsoft YaHei UI` → `Microsoft YaHei` → `Noto Sans SC`（Windows 中文优先，随包没有字体依赖）
- 字号：正文 13px；页面标题 20px/700；分组标题 13px/600；辅助文字 13px。
- 圆角：面板 10px，输入框/按钮 7–8px；不使用大圆角胶囊堆叠。
- 间距：页面外边距 20/18；分组内 12–16；控件最小高度不低于 32px，主要点击目标 44px。
- 焦点：所有可聚焦控件 2px 青瓷焦点环；导航按钮提供无障碍名称。
- 动效：只保留用户动作后的即时状态变化（按钮 hover/pressed、选中态），不做加载入场动画。

## 结构与状态

- 左侧 62px 导航轨道：聊天 / 历史 / 设置；当前页用青瓷底选中态，不靠颜色之外再堆装饰。
- 顶部状态行：会话标题（可增长）+ 连接状态 + 当前生效后端/模型 + 分析状态。状态文字允许压缩（`Ignored` 横向策略），不把整个页面撑出屏幕。
- 主区：聊天画面（只读，虚线占位）；下方识别文字（只读、限高）。
- 右侧：AI 建议面板（300px），单列建议，发送入口在每条建议旁；收起时只留竖排“AI 建议”拨片。
- 设置页：分组卡片按“微信连接 → 文字读取 → 对话分析 → 自动操作 → Codex 账户”排列；每个分组内部使用表单行，长说明在分组底部。保存入口固定在分析分组右侧，避免用户在长页面里找不到。
- 空状态：说明“连接后会出现什么”，而不是只说“暂无数据”。
- 错误/警告：靠近发生位置显示，文案说明后果与下一步；不道歉、不模糊。

## 无障碍与桌面细节

- 键盘：Tab 顺序按视觉顺序；按钮/复选框全部可聚焦并有焦点环；图标导航有 `accessibleName` 与 tooltip。
- 对比度：正文 `#1F2421` / `#F4F2EC` 与 `#6B746E`/白底均达到 WCAG AA 正文要求；青瓷主按钮白字对比约 5.9:1。
- 下拉框：滚轮不改变选择（`NoWheelComboBox`），避免滚动设置页误改模型/后端。
- 高 DPI：窗口最小 980×600；在 125%/150% 缩放下允许页面内容滚动、页面栈可压缩，不把 AI 面板挤到屏幕外。

## 10 个设计 Skills 的使用记录

| Skill | 本项目中的使用方式 |
| --- | --- |
| `ui-ux-pro-max` | 采用其可访问性/触达/字体与颜色/表单反馈优先级；检查对比度、焦点、选择控件误触。 |
| `frontend-design` | 确定“哑光纸 + 青瓷”的独立视觉身份、排版层级与写作语气，拒绝模板化 SaaS 观感。 |
| `impeccable` | 用于层级、状态、空状态与 UX 文案打磨；形成本文件的 token/规范。 |
| `web-design-guidelines` | 迁移其可访问性/键盘/焦点/语义标签检查项到 Qt 控件（accessibleName、焦点环）。 |
| `theme-factory` | 以自定义 theme token 的方式固化配色与字体，而不是套用现成主题。 |
| `canvas-design` | 用于本设计语言的静态视觉决策（色板/排版/空间），不生成运行时美术资产。 |
| `brand-guidelines` | 评估后不套用：Anthropic 品牌色会与“微信助手”的产品身份冲突；保留产品自有青瓷色。 |
| `web-artifacts-builder` | 不适用（Qt 桌面端）；迁移“组件状态一致、可复用样式”的思想。 |
| `react-best-practices` | 不适用（非 React）；迁移“避免无谓布局抖动/保持列表轻量”的性能原则。 |
| `webapp-testing` | 不适用（非 Web）；用 Qt offscreen + unittest + UIA 真实验收替代端到端点击测试。 |

## 验证

- `tests/test_ui_design_system.py`：无障碍名称、页面栈可压缩、空状态与预览尺寸。
- 全量 657+ 项测试在 offscreen 与真实 Windows 下通过；0.5.0 候选包做安装后截图复核。
- 真实微信内容不进入截图与测试；UI 截图仅使用未连接状态或合成数据。
