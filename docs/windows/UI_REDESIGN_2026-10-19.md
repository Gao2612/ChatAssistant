# ChatAssistant Lite 0.6.0：Windows 桌面端 UI/UX 全面重设计方案

## 一、信息架构：从功能堆叠转向任务工作台

产品定位为“微信会话理解与 AI 回复工作台”，核心任务是：连接微信、识别当前会话、理解上下文、生成回复、发送到微信。所有界面围绕这条主链路组织。

采用 左侧主导航 \+ 中央工作区 \+ 按需辅助面板 的统一架构，取消独立导航轨、三页并列与右侧抽屉相互竞争的模式。

建议左侧导航占可用宽度约 15%（设上下限），中央工作区占剩余空间，右侧上下文面板初始约占 25%。这些比例是布局目标而非固定像素。

### 2.2 900×500：紧凑模式

纯文本

`┌──────────────────────────────────────────────────────────────┐ │ ChatAssistant Lite ● 已连接 — □ × │ ├────────┬─────────────────────────────────────────────────────┤ │ 工作台 │ 当前会话：联系人 [上下文面板 ▸] │ │ ├─────────────────────────────────────────────────────┤ │ 档案 │ │ │ │ 微信预览 / 识别文字（可切换） │ │ 记录 │ │ │ ├─────────────────────────────────────────────────────┤ │ 设置 │ AI 回复建议 │ │ │ [建议一] [复制] [发送] │ │ ├─────────────────────────────────────────────────────┤ │ │ ● 已就绪 │ └────────┴─────────────────────────────────────────────────────┘`

紧凑模式下右侧面板默认收起，预览与识别文字采用分段切换，回复建议只显示必要操作。不得通过裁切控件、缩小字体或隐藏发送状态来适配窗口。

### 2.3 Qt 布局约束

- 主布局：`QHBoxLayout`，左侧导航、中间 `QStackedWidget`、可选辅助面板。
- 主工作区：`QSplitter(Qt.Horizontal)`；中央区域设置更高的 `stretchFactor`，避免窄窗口下被侧栏挤压。
- 工作台内容：`QVBoxLayout` \+ `QSplitter(Qt.Vertical)`，按可用空间分配预览区和回复区。
- 辅助面板：统一挂载在主窗口布局中，只存在一个 widget 实例；折叠通过隐藏面板并恢复中央区域空间实现。
- 最小窗口建议调整为 860×480；低于标准宽度时自动进入紧凑模式。导航、面板和按钮采用 `minimumWidth`、`sizePolicy`、布局伸缩因子，不再依赖 `setFixedWidth`。
- 高 DPI：尺寸统一使用逻辑像素，图标使用 SVG 或矢量绘制，避免按物理分辨率缩放。

交互规则：

- 加载： 显示进度指示器和具体任务名称；耗时操作使用非阻塞任务，不冻结主线程。
- 空态： 告知当前缺少什么，并提供一个明确的下一步操作。
- 错误： 展示用户可理解的原因、恢复建议及重试入口；技术详情进入诊断日志。
- 禁用： 发送条件不满足时禁用发送按钮，并说明缺失条件。
- 成功： 使用轻量状态提示，不用阻塞式弹窗打断连续操作。

## 四、关键流程状态机

主流程统一采用显式状态管理，避免定时器、按钮回调和后台任务各自维护互相冲突的 UI 状态。

纯文本

`启动 ↓ 检测微信窗口 ──未发现──→ 等待微信 / 刷新窗口 ↓ 已发现 选择会话 ──────失败────→ 显示原因 / 重试 ↓ 已选择 采集与识别 ────失败────→ 保留现场 / 重新采集 ↓ 成功 生成回复建议 ──失败────→ 重试分析 / 查看错误 ↓ 成功 用户检查并选择建议 ↓ 点击发送 发送中 ────────失败────→ 失败原因 / 安全重试 ↓ 成功 已发送 → 更新记录 → 返回可继续操作状态`

实现要求：

1. 后台任务使用 `QThread`、`QThreadPool` 或 `QRunnable`，通过信号向主线程回传结果。
2. 任务状态使用枚举定义，所有状态转移通过统一控制器处理。
3. 发送前再次校验微信窗口、目标会话和回复内容；失败时保留原始建议，不自动重复发送。
4. 网络请求设置超时、取消和重试上限。发送结果不确定时先核实实际发送状态，再允许重试，避免重复消息。
5. `tick`、`sync_dock`、`scan` 三个定时器分别承担明确职责，禁止重复触发同一项耗时任务。

### 5.2 字体、尺寸与动效

- 字体：优先 `Microsoft YaHei UI`，回退 `Microsoft YaHei`、`Segoe UI`。
- 字号：12px 辅助信息、13px 次级正文、14px 正文、16px 区域标题、20px 页面标题、24px 关键指标。
- 间距基数：4px；常用间距 4/8/12/16/24/32px。
- 圆角：输入框 6px、按钮 8px、卡片 12px、浮层 14px。
- 边框：默认 1px；键盘焦点 2px；阴影只用于浮层，普通卡片优先使用边框分层。
- 动效：悬停 120ms、面板展开 180ms、状态过渡 160ms。不得延迟关键操作，不得用动画代替加载状态。

## 六、分阶段迁移与验收

采用渐进式重构，不进行一次性重写。每阶段保留可运行版本，避免 UI 改造破坏微信采集、账号授权及发送能力。

建立基线与回归测试

固化当前 13 张截图、关键操作测试和窗口尺寸测试；记录连接、识别、生成、复制、发送、切号等功能的现有行为。

验收：现有关键流程有可重复的测试步骤；回滚可恢复到迁移前版本。

抽离设计系统

新建 [resources/styles/global.qss](<resources/styles/global.qss>)、[ui/theme.py](<ui/theme.py>) 和统一状态组件。优先统一主窗口、悬浮球、按钮和表单样式，不修改业务逻辑。

验收：两套视觉语言消失；主题切换和控件状态正常；样式可单独回滚。

重构主布局

先引入 `MainShell`、`NavigationBar`、`WorkspacePage`、`ContextPanel`，再将现有页面逐步挂载到新布局。先迁移布局容器，后调整视觉细节。

验收：1280×800 与 900×500 下无控件重叠、裁切；面板收缩不破坏主工作区。

拆分业务页面与控制器

将设置、档案、任务记录分别迁移到独立模块，使用信号槽连接原有业务方法。新旧界面通过功能开关切换，先验证再默认启用。

验收：原有功能入口均有对应映射；切换界面不丢失连接状态与任务结果。

补齐状态管理并发布

统一加载、空态、失败、重试、取消与发送反馈；将窗口版本号改为从 `build_info` 读取，检查 PyInstaller onedir 打包和 Inno Setup 安装升级。

验收：核心流程回归通过；干净环境安装启动正常；异常有日志；旧版本可回退。

## 七、明确不做的事与风险控制

1. 不重写业务底层。 微信采集、账号授权、历史迁移、模型分析和发送逻辑继续复用现有实现。
2. 不同时改变协议与 UI。 网络请求格式、数据库结构、账号存储及数据迁移不属于本次视觉重构范围。
3. 不把所有功能塞进首页。 首页聚焦当前会话；历史分析、配置与诊断按需进入对应区域。
4. 不滥用固定尺寸、弹窗与动画。 确认操作仅用于真正不可逆或影响范围大的行为，普通错误采用非阻塞反馈。
5. 不直接覆盖现有脏工作树。 当前有 18 个文件存在未提交改动，应先确认改动归属并建立可回滚基线，不能用重置或覆盖的方式清理。
6. 重点风险： 微信窗口和会话状态同步、悬浮球与主窗口的生命周期、后台任务并发、打包资源路径及旧配置兼容。必须纳入回归测试。

最终验收门槛： 主工作流可连续完成；窗口缩放正常；所有耗时操作不冻结 UI；所有关键任务具备成功、失败、加载和空态；现有功能无回归；新版本能正常安装、升级和回滚。
