## 需求与边界

依据已讨论并接受的简化方案：配置官方微信路径；用户手动启动和登录；程序自动发现单个窗口，多个窗口手动选择；当前可见对话本地 OCR；显示可能意图、建议动作和三条回复；复制后用户自行发送。
默认保持官方微信独立。已失败的 SetParent 原型不作为默认入口，不因嵌入阻塞采集。
模型后端分为官方 Sign in with ChatGPT 套餐授权和用户自行配置的 OpenAI 兼容 API。订阅需在本应用单独登录/授权，并从账号返回的模型目录选择；不声称镜像 Codex 桌面当前模型/额度。API key 由 Windows DPAPI 保护。分析时仅发送当前可见对话；自动分析默认开启，并且只有模型已配置、快照稳定时才发请求。
不落盘聊天与截图，不读取微信数据库，不自动发送。历史导入和完整多账号数据库不属于本次。

## 架构与复用

新增 windows/lite 独立 Python/PySide6 程序；复用 jev-chat/jev-chat-windows 的本地 OCR 气泡解析和像素消息区定位，保留上游许可与固定提交号。
窗口枚举使用完整进程路径，不使用窗口标题作为唯一身份；连接生命周期使用 session generation；上下文只取当前可见快照，过期网络结果不显示。
界面、窗口发现、采集子进程、模型调用和配置分别独立。原 Qt Fluent UI 不引入，使用标准 PySide6 Widgets。

用户补充的 [FerryCorleone/crush-monitor](https://github.com/FerryCorleone/crush-monitor) 作为历史文本分析参考：可借鉴其逐句结构化分析、长文本分批和模型设置体验；不适用于实时窗口采集，也不照搬恋爱场景的评分规则。历史版仍以 ExportWeChat HTML 导入和本地项目分析为准。

## 重点验证

1. 切换窗口、切换对话、暂停、修改设置后，旧模型结果必须失效。
2. 相同文本的真实连续消息保留；不通过全文永久去重吞消息。
3. 标题无法识别时不沿用上一会话，不自动分析。
4. 无 key/网络失败/非法模型输出可恢复，错误不显示密钥或服务响应体。
5. 非微信同名窗口不误接；不能捕获最小化窗口时不自动还原或抢焦点。

## 交付与限制

源码及便携包；初始只支持可见的文字气泡，OCR 可能误判；建议仅提供复制，用户自行核对和发送。
没有真实模型密钥时使用本地服务器测试请求/响应，明确未验证真实远端模型调用。
原型自检通过不等于 Windows 微信所有版本兼容；记录本次实际环境与未测范围。

## 用户批注后的正式 UI 改版（2026-10-16）

目标：把已在 Codex 侧栏预览确认的布局落入 PySide6 应用；侧栏标志使用抽象对话气泡图形；导航为左侧“聊天 / 设置”；微信窗口连接和模型入口全部收进设置页；聊天主区显示独立微信窗口的当前 OCR 快照；右侧 AI 建议面板默认收起、由窄标签展开。移除手动分析、暂停校正、手动粘贴和自制批注界面。微信窗口仍独立运行，界面不得声称真实交互嵌入。

自动分析偏好持久保存并默认开启；只有用户选择的模型服务有效、采集快照稳定且会话版本未变化时才发起分析。设置页明确说明会发送当前可见对话文本给所选模型；回复只允许复制，不能自动输入或发送微信。
