## 1. 已确认的产品目标

提供 Windows 桌面程序及 exe 安装包，普通用户不需要安装 Python 或配置开发环境。
用户在本软件内部使用官方微信登录界面和聊天界面；支持多个微信账号，使用账号列表或标签切换。
提供两个独立业务界面：
1. 实时聊天助手：判断当前对话的意图、需求与风险，生成回复建议；建议可复制或填入，发送由用户确认。
2. 历史分析任务：导入 ExportWeChat 导出的 HTML 文件或目录，或选择本软件本地保存的聊天记录，创建客户画像、关系趋势、聊天统计任务。

“本地保存的聊天记录”在第一版指本软件导入、采集和管理的记录，不指直接读取微信加密数据库。
实时采集得到的内容不等于完整微信历史。导入数据也只能代表实际导出的范围。
用户没有要求自动发送、直接读取微信数据库、修改微信程序或实现第三方微信协议客户端。

## 3. 产品界面与主要流程

### 3.1 实时聊天工作台

布局建议：左侧账号与联系人资料，中间官方微信窗口容器，右侧分析与回复建议。
顶部显示当前账号、微信连接状态、采集开关、当前会话。
流程：启动/连接微信 → 在嵌入区域扫码 → 绑定账号槽位 → 打开会话 → 读取可见消息 → 判断 → 生成三条建议 → 用户复制或填入 → 用户发送。
分析显示可能意图、对方需求、建议动作、风险提示、使用的上下文范围。
提供“重新分析”“调整语气”“暂停分析”；识别不确定时允许校正正文、发送人和会话绑定。
不得把模型推断称为“真实意图”，用可能、依据和不确定性表达。
填入前重新检查当前账号、窗口、会话和消息版本，切换会话后旧候选失效；验证失败只允许复制。
运行期间是否保存 OCR 消息由用户控制；截图默认只在内存，文本持久化开关和保留期限明确展示。

### 3.2 历史分析任务页

提供任务列表、导入入口、本地会话选择、时间筛选、分析模板、进度、取消/重试和报告浏览。
导入流程：选 HTML/目录 → 本地安全解析 → 预览发送人、日期、消息数量、附件情况 → 绑定微信账号和会话 → 确认导入 → 创建任务。
账号无法从导出文件可靠确定时必须让用户绑定，禁止按名称自动合并。
任务页与实时工作台各自运行；批量分析不阻塞聊天和截图采集。
报告显示数据范围、来源、缺失字段、未识别消息、模型、生成时间和证据链接。
支持从本地会话重新分析；历史报告可以经用户确认作为实时助手参考，不自动覆盖联系人事实档案。

### 3.3 三类分析内容

客户画像：明确表达的需求、关注产品、预算与时间约束、沟通偏好、跟进事项及依据。不存在证据的字段标为未知。
关系趋势：按时间窗口整理互动频率、双方主动程度、话题和表达变化；不把消息频率直接当作关系质量。
聊天统计：总消息数、双方占比、活跃日期/时段、消息类型、群聊发言人分布。
回复耗时只在时间与发送人可靠、定义清楚时计算；排除系统消息并明确按连续消息段还是单条消息统计。
报告区分确定性统计、显式资料和模型推断。所有推断能够追溯相关原始消息。
图表与统计由本地代码计算，模型负责解释与文本整理，不能让模型凭空生成计数。

## 4. 推荐技术路线与模块

推荐以 Electron + React + TypeScript 建立桌面壳、历史任务和模型接口，
复用本仓库已整理的 crush 源码与验证基准。
Windows 原生窗口、WGC 与 OCR 能力通过独立连接器接入；
是否需要 Python 或其它原生进程由采集验证结果决定，不预先要求改写分析模块。
crush 便携打包只作为构建基础，正式产品仍需安装、升级与卸载设计。
推荐新增独立 windows/ 工程，保留现有 Android app/ 构建，不在 Android 源码中硬塞桌面逻辑。

模块：
- DesktopShell：工作台、任务页、资料页、设置和状态展示。
- WeChatHost：发现官方微信安装、启动/连接、窗口嵌入、恢复、进程退出处理。
- AccountSessionManager：内部账号 ID、进程与窗口绑定、多账号切换和失效处理。
- LiveCapture：截图、消息区定位、OCR、来源与识别质量标记。
- ConversationRouter：账号/会话路由、切换检测、顺序与版本维护。
- ContextBuilder：近期消息、人工资料、用户允许引用的历史摘要。
- AnalysisEngine：实时判断、回复生成、排序、结构化结果校验。
- HtmlImport：版本化 HTML 适配、预览、附件映射、解析告警。
- RecordStore：SQLite、原始导入文件索引、检索、去重和数据迁移。
- TaskRunner：持久化任务、分段处理、进度、取消、重试、恢复。
- ReportBuilder：本地统计、模型摘要、证据索引、报告导出。
- ModelGateway：接口配置、超时、退避、用量估算、密钥脱敏。
- Installer：程序、OCR 模型和运行依赖打包、安装、升级、卸载。

实时流：官方微信窗口 → 本地截图/OCR → 账号与会话确认 → 内存上下文/可选存储 → 模型 → 分析与候选。
历史流：HTML 或本地消息 → 规范化消息库 → 任务快照 → 本地统计/分段模型分析 → 报告。
数据层不依赖 UI；OCR、HTML 和分析模块通过稳定结构交互。

## 5. 微信嵌入与多开：必须先验证的部分

嵌入是托管官方微信的外部窗口，不是重新实现微信登录协议。
可研究 Win32 SetParent + 窗口样式调整 + 尺寸同步；不能宣称 API 存在就等于微信支持。
微软文档指出不同 DPI awareness 的窗口重设父级可能导致异常：
https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setparent

验证场景：
- 扫码登录到主窗口时句柄变化、会话恢复、退出重登。
- 中文输入法、焦点、快捷键、滚动、复制粘贴、用户发送。
- 100%/125%/150%/200% 缩放，多显示器和跨屏拖动。
- 图片预览、文件选择、菜单、模态弹窗；弹窗未必随主窗口嵌入。
- 窗口嵌入后 WGC 是否仍能稳定截图、OCR 和坐标是否正确。
- 软件关闭或崩溃后微信窗口恢复可操作；对已连接窗口记录并恢复原父级、样式和位置。
- 多个账号是否能够正常同时登录，账号切换后采集和填入是否准确。
- 非当前账号窗口不渲染时的处理，不承诺所有后台账号同时实时采集。

多开不预设实现方式。先记录用户微信版本、Windows 版本及已有多实例能力；不得通过结束用户微信、修改微信二进制或解除未知互斥锁来假定多开可用。
账号初次可使用人工命名的内部槽位，进程 PID 和窗口 HWND 仅用于本次连接，不作为永久身份。
主产品目标仍是内嵌；若失败，联动排列是需用户接受的备选，不得静默替换需求。

## 6. ExportWeChat HTML 导入设计

尚未提供 ExportWeChat 仓库地址、版本或导出样本，不能确定 DOM 选择器和字段结构。
第一步收集脱敏样本：单聊、群聊、多个日期、连续重复消息、图片/语音/文件、引用/系统消息及缺失附件。
按样本创建格式识别器和版本化解析器；未知格式返回明确错误与预览，不猜测发送人和时间。
解析产物包含 raw_text、规范化正文、发送人、方向、原始时间、规范化时间、消息类型、附件引用、源文件/源位置、告警。
时间无年份或时区时保留原文和精度，要求配置来源时区；不默默填当前年份。
群聊保留发言人，未知方向标记 unknown；语音无现成转写时保存附件占位，第一版不承诺转写。
缺失附件可以继续导入文字，但报告说明不包含附件语义。

HTML 只作为待解析数据，不在有执行权限的浏览器中打开，不执行脚本、不加载远程资源。
附件路径只允许落在用户选定的导出目录内，拒绝路径穿越；限制文件大小、数量与解析资源。
大文件增量处理、预览抽样，正式导入用事务批次，支持取消和失败回滚/续传。
保存导入文件哈希与解析器版本，便于重复导入识别、故障复现及重新解析。

## 7. 本地数据模型与去重

推荐 SQLite + 应用数据目录，媒体存储为索引或用户允许复制的文件。
核心表：
- accounts：account_id、显示名、用户绑定信息、创建时间。
- conversations：conversation_id、account_id、类型、名称、外部标识、人工绑定状态。
- participants：participant_id、conversation_id、名称、别名、身份来源。
- messages：message_id、account_id、conversation_id、participant_id、direction、timestamp、time_precision、type、text、source_kind、quality、sequence。
- imports：import_id、文件哈希、解析器版本、账号、导入状态、条数、告警。
- message_sources：message_id、import_id/采集批次、原文件位置、外部消息 ID、原始序号。
- attachments：attachment_id、message_id、原始路径、已验证路径、存在状态。
- contacts/notes：人工事实、关系备注、标签、变更时间。
- analysis_tasks：task_id、类型、范围、状态、进度、模型配置、消息快照、错误。
- task_chunks：分段、输入哈希、状态、结果引用、重试次数。
- reports/report_evidence：报告版本、统计、推断、证据消息列表。
- schema_migrations：数据版本及迁移记录。

所有消息、任务和检索必须通过账号与会话限定。名称不是稳定 ID。
去重层次：
1. 同一导入文件哈希：重复导入提示并跳过。
2. 同账号/会话内可靠外部消息 ID：精确去重。
3. 无外部 ID 的重叠导出：结合发送人、时间、类型、正文、原始顺序与邻接上下文匹配；含糊时保留并标记候选重复。
4. OCR 只做相邻帧序列对齐，不能把“相同人＋相同文字”当永久唯一键。
历史导入与 OCR 跨来源合并必须保守，不能自动删除真实重复消息。
默认不跨账号合并联系人；用户显式关联时保留原账号来源。
原始消息事实与模型生成的画像分开存储，可删除/重算模型结果而不损坏记录。

## 8. 实时分析与历史任务执行

实时：消息变化去抖、消息区局部处理、上下文上限、切换时递增版本号。
模型结果携带 account_id、conversation_id、revision；过期结果丢弃，防止给错账号回填。
模型失败不影响官方微信；提供重试和复制，错误文本脱敏。
来自聊天的内容均为待分析数据，不作为系统指令；结构化输出校验，提示注入不改变程序权限。

历史：创建任务时冻结消息范围/输入版本，后续导入不改变正在运行的任务。
状态：queued → running → completed；可转 cancelling/cancelled/failed/interrupted。
阶段：数据检查 → 统计 → 按时间/主题分段 → 分段摘要 → 聚合报告 → 证据检查。
按 token 预算分段并保留必要重叠；证据必须引用实际 message_id。
缓存键包含输入哈希、模型、模板和参数；更换配置不能误用旧结果。
先显示消息范围、预估请求数与费用区间（能够估算时），用户触发后才提交文本给配置的接口。
支持取消、限并发、退避；崩溃后从已完成分段恢复，失败分段可重试。
实时请求优先，历史任务限并发，避免挤占交互资源。
画像摘要受用户确认后才进入长期实时上下文；统计不能被模型推断覆写。

## 9. 数据与发布边界

聊天原文件、消息库和报告保存在用户设备，不上传到 GitHub；仓库只放代码、方案和脱敏测试样本。
本地 OCR 不代表全链路离线：使用云模型时会发送所选消息文本与资料，界面应说明目的地和范围。
密钥建议使用 Windows Credential Manager 或 DPAPI 保护；不进入日志、报告、安装包和仓库。
诊断日志只保留错误代码、耗时、条数和组件版本；支持删除本地记录、报告与缓存。
解析后的正文以纯文本渲染；禁止执行导出 HTML 中的脚本。
软件默认使用普通用户权限；不为窗口嵌入要求永久管理员权限。

建议 PyInstaller onedir + Inno Setup 生成 exe 安装包，OCR 模型随安装包提供。
程序与用户数据分离，用户数据放 LocalAppData 下的产品目录；升级前备份数据库并执行可恢复迁移。
卸载是否删除聊天数据由用户选择，不默认清空。
发布时核查依赖许可、来源说明、安装升级测试、签名条件及版本说明。
官方微信作为外部依赖：检测已有安装或引导用户安装，不预设允许随产品重新分发微信安装包。

## 10. 分阶段交付与验收

### P0：可行性验证

输入：实际 Windows/微信版本、是否需要同时采集后台账号、ExportWeChat 脱敏样本。
输出：嵌入/多实例/OCR 可行性报告、HTML 字段映射、推荐依赖方案。
通过标准：一个账号在容器内完成登录和聊天；输入法、窗口缩放及关键弹窗可用；嵌入后可采集；退出能恢复窗口。
多账号另行实测，不能用复制两个 UI 面板代替验证。
HTML 样本按人工标注核对条数、顺序、方向、日期和附件映射。
失败项列出具体版本和条件；不把未测试的场景写成通过。

### P1：单账号实时闭环

实现窗口托管、采集开关、判断与三条建议、复制/回填、模型设置。
验收：切换会话和消息更新后旧结果失效；识别失败能提示和校正；没有自动发送；模型断网仍可正常聊天。
用脱敏标注样本测 OCR 与方向识别，记录误差，不仅验证接口返回 200。

### P2：HTML 导入与本地消息库

实现格式识别、预览、账号/会话绑定、导入、检索和删除。
验收：重复导入不新增重复批次；真实连续重复消息保留；群聊发言人、时间精度和未知值正确；恶意 HTML/越界附件不执行或访问。
验证导入取消、坏文件、大文件和数据库迁移。

### P3：历史分析任务

实现三类模板、统计、分段、进度、取消/恢复和证据报告。
验收：本地统计与人工基准一致；每个关键画像推断可定位原文；未知信息不补造；任务恢复不重复提交已完成分段。
新增导入不改变已有任务快照；实时聊天保持响应。

### P4：多账号与历史上下文联动

在已验证多实例方式上实现账号切换、独立记录和任务范围。
验收：两个账号存在同名联系人仍完全隔离；账号 A 的建议不得填入账号 B；关闭一个微信不破坏另一个。
历史摘要只有确认后引用；非当前账号的采集范围明确说明。

### P5：安装与发布

生成完整 exe 安装包，包含程序与 OCR 依赖，提供版本信息和来源说明。
验收：干净 Windows 测试机无需 Python 可安装启动；断网可完成导入、本地统计和界面操作；云分析明确提示网络要求。
验证升级保留数据、迁移失败恢复、卸载保留/删除选项。
