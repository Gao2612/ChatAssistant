## C. 已知限制/风险（不阻塞但需知道）

1. **OCR 名字误识**：部分联系人（如“郜亚禹”被读成“部亚禹/鄢子夜”）会使自动查找安全失败；不会切错人，但需要人工改名/手动操作。
2. **应用内自动找对话的跨进程自动化不稳定**：代码级真实成功，UI 跨进程触发仍偶发失败；以人工点击为准（A3）。
3. **托盘捕获窗口状态**：0.5.6/0.5.7 已用 `SWP_HIDEWINDOW` 原子恢复并二次隐藏；真实微信“点击托盘恢复”的用户路径需在 A5 中人工确认一次。
4. **D-UI 布局**：1000×520 / 最小 900×500 下已截图确认不裁切；其他 DPI/多显示器组合未逐一实测。
5. **真实模型只用合成数据**：凭据恢复后也只发送合成聊天/历史，不保存真实聊天内容。
6. **安装包版本**：当前安装的是 0.5.7；后续若再改代码需重新打包并更新本文件与验收矩阵。

## D. 用户操作最短路径（建议顺序）

1. 打开 **0.5.7**（`E:\ChatAssistantLite`）→ 设置 → 对话分析 → 兼容 API：**重填真实 DeepSeek Key 并保存**（或恢复 ChatGPT 额度）。
2. 设置 → 自动操作 → 输入“田子夜” → 点 **自动查找并切换对话**，记录提示（A3）。
3. 连接微信 → 关闭微信到托盘 → 观察识别文字是否保持/更新 → 点“启动微信”恢复（S-V04 人工确认）。
4. 需要时测试一次发送（A4）；导入测试聊天记录做 S-V07/S-V08/S-V11。
5. 两个窗口条件允许时跑 S-V09 30 分钟。
6. 把每项结果/提示原文发回；代理随后修缺陷、同步矩阵与看板，直到 T12 签收。
